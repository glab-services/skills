# Follow-ups — flow-product-level

- **FR1-1 — hard links on the shared store.** Review round 1 (A2) makes `plan-gate.sh` publish each report and verdict with `ln`. A store on a filesystem without hard links (some network or FAT-family mounts) now fails every write with exit 2, `plan-gate.sh: writing <path> failed`; before, `mv` worked there. UNVERIFIED on any such mount; nothing in this repo names which filesystems a store may live on. Out of scope: the decision chose `ln`.
- **FR1-2 — a claim left by a killed run.** Review round 1 part 2 (A2) claims each report and verdict number with a file `.plan-gate.claim.<report|verdict>.r<n>` in `briefs/<project>/`, which the trap removes. A run killed by SIGKILL, or by a host crash, leaves its claim, and every later run for that number is refused `another run is writing report r<n>` (or `verdict r<n>`) until someone removes the file by hand. Proven with a planted claim: `REFUSED: another run is writing report r1`, `rc=1`. The refusal does not say the claim may be stale or where it is. Out of scope: the decision fixes the claim's mechanism, not its recovery.
  - Review round 2 (finding 1): the refusal now names the claim file and says to remove it by hand when no run is writing (`REFUSED: another run is writing <report|verdict> r<n>; when no run is writing, remove <store>/briefs/<project>/.plan-gate.claim.<report|verdict>.r<n> by hand`), tested by T38. Still open: nothing tells a stale claim from a live one, so a person decides.
- **FR2-1 — a signal while `ln` runs.** Review round 2 (finding 2) clears `TMP_DIR` right after `ln` succeeds, before the `rm`. bash runs the trap of a TERM that lands while `ln` is still running as soon as `ln` exits, before the next command, so a TERM in `ln`'s own lifetime still removes `plan.r<n>/` of a report that is linked. Proven with an `ln` stub that links, then waits 2 s: `report run rc=143`, the project folder `brief.md report.r1.md`. The window is now `ln`'s run time, not `rm`'s. Out of scope: the decision fixed the order, not the window; closing it needs the signals held off across the `ln` (for example `trap '' TERM HUP INT` around it), which the review did not ask for.
- **FR2-2 — a temporary file left by SIGKILL.** Review round 2 (finding 5) names the temporary file `.plan-gate.tmp.<report|verdict>.r<n>`. A run killed by SIGKILL leaves it beside its claim, and the claim's refusal names only the claim. The next run that takes the claim removes it (T38). Out of scope: the finding asked for the trap to reach the file, which it now does on every signal it sees.
