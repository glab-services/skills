BLOCK: 3 issues

1. plugins/glab/scripts/plan-gate.sh:96-98, 191, 227 (low, correctness and comment). The hold_signals comment says a signal that lands between the create and `CLAIM=$1` "no longer leaves a claim behind". That holds only for a signal sent to bash. The create runs in a `( ... )` subshell, and a subshell resets caught traps. So a Ctrl-C (INT to the whole process group) that lands after the open kills the subshell. The `if` then fails, CLAIM stays unset, and release_signals re-raises: the claim is left. If the line was already written, a later Linux run takes it over. If the open happened but not the write (empty line), or the host has no /proc, a person has to remove it. The lock create at :227 has the same gap, and a leftover lock is never taken over, so it always needs a person. Proven with a stand-in: `setsid bash -c 'trap "HELD=INT" INT; if (set -C && umask 022 && printf ... >claim && kill -INT 0 ...); then ...; else echo "subshell rc=$? HELD=$HELD CLAIM unset"; fi'` printed `subshell rc=130 HELD=INT CLAIM unset`, and `claim` stayed with its line. Fix: do the create in the main shell (save the umask, `set -C`, `printf '%s\n' "$ME" >"$1"`, `set +C`, restore the umask) for both the claim and the lock. Otherwise, when the subshell fails with HELD set, adopt the file whenever its first line equals a non-empty ME. At the least, correct the comment.
