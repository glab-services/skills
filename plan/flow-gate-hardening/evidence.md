## State transitions

- **A claim** `.plan-gate.claim.<kind>.r<n>`: absent → made by `claim` (`O_EXCL`, the line `ME`, mode 644) → removed by its run's trap. Killed by SIGKILL: stays, with the tmp if the run had made it, and for a report possibly `plan.r<n>/`. A later run: owner provably gone → under the lock, the same line read again → tmp and claim removed → its own claim made → lock removed; owner alive → refused, today's text; cannot tell → refused, naming the tmp too when there is one. After a takeover, the report's tests under the claim run as before: a leftover `plan.r<n>/` is refused and kept (T43).
- **The lock** `.plan-gate.takeover.<kind>.r<n>`: absent → made by `take_over` (`O_EXCL`) → removed by it a few commands later, or by its trap. Left only by a SIGKILL inside that stretch; then every takeover of that number is refused naming it.
- **The publish**: tmp complete and mode 644 → signals held → `ln` → published (or `ln` killed after linking: `-ef`, published) → `TMP_DIR` cleared → signals released (a held one ends the run here, the trap leaving the copy) → tmp removed. `ln` failed otherwise: the name there → refused; else exit 2 naming the requirement; the trap removes the copy, the tmp and the claim.

## Ownership and lifecycle

- The claim and the lock are opened and closed by bash itself in a subshell (`set -C`, `umask 022`, one `printf`); no descriptor outlives the subshell. `ln`'s stderr is read through `$( )`, which bash closes when `ln` exits. Only the trap and `take_over` remove claims; only `take_over` removes another run's.

## Rejected boundaries

- **`kill -0` alone as the proof**: a pid namespace (a sandbox) or `hidepid` makes a live run's pid look absent, and a reused pid looks alive; the line adds host, boot id, pid namespace and start time (E2, E5).
- **`flock`**: the kernel would drop the lock with its holder, but it is util-linux, not on macOS, and not what the script requires.
- **A takeover by `mv` of the stale claim**: a second taker's `mv` can move away the new owner's live claim, and putting it back is not exclusive.
- **A fallback to `mv` on a store without hard links**: `mv` overwrites, so only the claim would keep two runs apart; it could not be proven on any such filesystem here (E4), and FAT fails `chmod` first.
- **A fallback that writes the final name with `O_EXCL`**: a reader can see the file half written; telling that needs an end marker in the report and verdict formats, which changes the trace and every file that states those lines.
- **Detecting the missing hard links from `ln`'s message**: one errno, two texts (E3).
- **A permanent test of the claim window**: it needs an instrumented copy of the script; it is a post instead (E7, `plan.md` A5).
